A maintenance release: no new entities, no behavior changes to existing
ones. Safe to update from 0.9.0 — nothing to do afterwards.

## Fixes

- **Clearer failure when `catalog.yaml` is missing.** 0.9.0's notes said an
  incomplete install "aborts with a `CatalogError`"; it actually raised a
  bare `FileNotFoundError` that gave no hint about the cause. Every catalog
  load failure (missing, unreadable, malformed) now raises `CatalogError`,
  and the missing-file case names the fix:

  > `catalog.yaml is missing from /config/custom_components/sungrow_isolarcloud.`
  > `When installing manually, copy the whole custom_components/sungrow_isolarcloud`
  > `folder, not just the Python files.`

- **`scripts/live_smoke_test.py` was broken by the 0.9.0 refactor** — it
  still imported the deleted `points` module and failed on startup. It now
  reads the catalog like the rest of the integration. (Developer tool
  only; no effect on the integration itself.)

- An uncataloged point reporting **millivolts** got no device class, while
  a cataloged one did. `mV` now maps to the voltage device class on both
  paths.

## Documentation

- New **[contributing guide](https://github.com/steven-g-w/HA-Sungrow/blob/main/docs/contributing.md)**:
  development setup, tests, and how to add sensors, controls and whole
  device types via `catalog.yaml` — normally with no Python changes. The
  README's Development section moved there.
- README corrections: the device-control section claimed no parameter
  polling happens while control entities are disabled; in fact the
  parameters are read once when the entry loads, and only *recurring*
  polling is suppressed. Manual-install steps and troubleshooting now
  mention `catalog.yaml`, and the project banner was rewritten to describe
  the actual limitation (verified against one hardware combination)
  instead of a blanket "not ready for general use".

## Internal

- `pyflakes` is now a test dependency and runs in CI, so the lint check
  the contributing guide asks for is actually enforced.
