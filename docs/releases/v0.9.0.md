## ⚠️ Heads-up: the mapping engine was rewritten in this release

The entire iSolarCloud→Home Assistant mapping (which points are polled,
how they become sensors, which parameters are writable) moved out of
Python code into a single declarative file shipped with the integration:
`custom_components/sungrow_isolarcloud/catalog.yaml`. The runtime code is
now agnostic of the mapping and only interprets that file.

**What this means for you:**

- **Entity unique IDs are unchanged.** Existing entities, dashboards,
  automations, history and Energy-dashboard settings are preserved.
- **HACS installs:** update as usual, nothing to do.
- **Manual installs:** copy the **entire**
  `custom_components/sungrow_isolarcloud` folder. If the new
  `catalog.yaml` is missing, setup aborts with a `CatalogError`.
- Entity behavior is pinned by a golden snapshot test and was verified
  unchanged during the migration. If you still spot a sensor with a
  different name, unit or class after updating, please
  [open an issue](https://github.com/steven-g-w/HA-Sungrow/issues).
- On **fresh installs only**, a few auto-generated entity ID slugs may
  differ from what a fresh install of 0.8.0 produced (e.g.
  `binary_sensor.sh10rt_problem`); existing installs keep their IDs.

**Why:** adding support for a new sensor, control or whole device type is
now a YAML-only change — see
[docs/declarative-catalog-design.md](https://github.com/steven-g-w/HA-Sungrow/blob/main/docs/declarative-catalog-design.md)
for the schema and design.

## Changes

- All measuring points, writable parameters, economics fields, unit
  mappings and backfill selections now live in `catalog.yaml`, validated
  at startup with clear error messages (bad enum values, duplicate param
  codes, etc.)
- New `docs/declarative-catalog-design.md` describing the schema and the
  code/data boundary
- New golden snapshot test asserting every entity's identity,
  classification, unit and state; new catalog validation tests
- New step-by-step credentials guide with screenshots
  (`docs/getting-credentials.md`)
